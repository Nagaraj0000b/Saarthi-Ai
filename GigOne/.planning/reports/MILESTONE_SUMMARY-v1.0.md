## 1. Overview (The "Why")
Milestone v1.0 was initiated to address structural biases in the GigOne Saarthi recommendation engine. Previously, the system used inconsistent job categories and unfairly penalized remote/digital workers for environmental factors like weather and traffic, which do not impact their productivity. 

The goal was to deliver **unbiased, highly accurate earning predictions** by restructuring the data foundation and retraining the core XGBoost model.

## 2. Architecture (The "How")
The system follows a three-tier ML architecture:
1.  **Data Generation Layer** (`generate_dataset.py`): A probabilistic simulator that creates high-fidelity synthetic data based on real-world gig economy patterns in India.
2.  **Training Layer** (`train_model.py`): Uses **XGBoost** with categorical encoding and regularization to predict hourly earnings based on 22 features.
3.  **Inference Layer** (`main.py`): A **FastAPI** service that provides real-time recommendations, now enhanced with user-specific filtering logic for skills and job registrations.

**Key Technical Change**: Introduced an exclusion logic in the data generator to prevent weather/traffic multipliers from affecting "Remote service providers," ensuring the model learns a zero-impact relationship for these roles.

## 4. Decisions (The "So What")

| Decision | Rationale | Impact |
|----------|-----------|--------|
| **Standardize 5 Categories** | Previous "Other" category was ambiguous and led to poor recommendations. | Clearer UX and more precise model features. |
| **Environmental Decoupling** | Remote/Digital work is immune to rain/traffic. | Fairness: Remote workers now see stable earning predictions regardless of outside conditions. |
| **Inference-Time Filtering** | Users shouldn't be recommended jobs they can't actually do or aren't signed up for. | Drastically improved recommendation relevance and user trust. |
| **Pytest Implementation** | Manual scripts were prone to silent failures. | Robust, automated verification for future changes. |

## 6. Tech Debt & Next Steps
- **Label Encoding Consistency**: Identified that label encoders are case-sensitive (e.g., 'Low' vs 'low'). Future versions should normalize inputs to lowercase before encoding.
- **Model Explainability**: SHAP summary plots are generated but not currently exposed via the API.
- **Real-world Feedback Loop**: The system currently relies on synthetic data. The next milestone should focus on integrating real user earning feedback to "fine-tune" the predictions.
